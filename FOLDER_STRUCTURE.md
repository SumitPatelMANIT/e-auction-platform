# E-Auction Management System - Folder Structure

This document outlines the folder structure of the E-Auction project. The project follows a modern monorepo-style structure, split cleanly between a Node.js `backend` and a React `frontend`. 

Understanding this structure helps in navigating the codebase, understanding where business logic lives, and knowing where to add new features.

---

## 📁 Root Directory (`e:\E-auction\`)
*   **`backend/`**: Contains the entire server-side application (Node.js + Express + Prisma).
*   **`frontend/`**: Contains the entire client-side application (React + Vite + Tailwind).
*   **`logo.png`**: The master copy of the application's logo.
*   **`TECHNOLOGIES.md`**: Documentation of the tech stack.
*   **`FUNCTIONALITY.md`**: Documentation of system architecture and module connections.
*   **`FOLDER_STRUCTURE.md`**: This file.

---

## 🖥️ Backend Structure (`/backend`)
The backend follows a standard MVC (Model-View-Controller) inspired architecture, tailored for REST APIs.

```text
backend/
├── prisma/                 # Database Configuration
│   ├── schema.prisma       # DEFINES THE DATABASE: Contains all table definitions (Models) and relationships. Why? Centralizes the database schema so Prisma can generate TypeScript/JS client code and manage SQL migrations.
│   └── migrations/         # History of database changes generated by Prisma.
├── src/                    # Main Source Code
│   ├── controllers/        # BUSINESS LOGIC: Contains functions like `adminController.js`, `bidderController.js`. Why? Keeps logic out of route files. They receive the HTTP request, interact with the database, and send the HTTP response.
│   ├── routes/             # API ENDPOINTS: Defines URLs (e.g., `/api/admin/users`) and links them to the correct controller. Why? Makes the API easy to map and navigate.
│   ├── middleware/         # REQUEST INTERCEPTORS: Contains auth checks. Why? To verify JWT tokens and check user roles before allowing access to secure routes.
│   ├── utils/              # HELPERS & BACKGROUND JOBS: Contains `cronJobs.js` and formatting functions. Why? To isolate background tasks (like auto-closing auctions) from HTTP requests.
│   └── index.js            # SERVER ENTRY POINT: Where the Express server and Socket.io server are initialized and started.
├── .env                    # Environment variables (Database URL, JWT Secrets). 
└── package.json            # Lists Node.js dependencies and start scripts.
```

## 🎨 Frontend Structure (`/frontend`)
The frontend follows a feature-based and component-based architecture standard for modern React applications.

```text
frontend/
├── public/                 # STATIC ASSETS: Contains files like `vite.svg` and `logo.png`. Why? Files here are served exactly as they are without being processed by Vite's bundler.
├── src/                    # Main React Source Code
│   ├── components/         # REUSABLE UI: 
│   │   ├── layout/         # Structural components like `Navbar.jsx` and `Footer.jsx`.
│   │   └── ui/             # Generic, reusable pieces like Buttons, Cards, and Inputs. Why? Promotes code reuse and UI consistency.
│   ├── pages/              # FULL VIEWS (Routes): Organized by user role.
│   │   ├── admin/          # Admin screens (e.g., `SystemDashboard.jsx`, `AuctionLifecycle.jsx`).
│   │   ├── bidder/         # Bidder screens (e.g., `CatalogueSearch.jsx`, `MyBidsDashboard.jsx`).
│   │   ├── seller/         # Seller screens (e.g., `InventoryDashboard.jsx`).
│   │   └── shared/         # Common screens (e.g., `Home.jsx`, `Login.jsx`, `Register.jsx`).
│   ├── context/            # GLOBAL STATE: Contains `AuctionContext.jsx`. Why? Uses React Context to share live Socket.io data (like incoming bids) across multiple components without "prop drilling".
│   ├── hooks/              # CUSTOM HOOKS: Reusable React logic (e.g., `useAuth` or `useSocket`).
│   ├── App.jsx             # ROOT COMPONENT: Defines the React Router structure and wraps the app in necessary Context Providers.
│   ├── main.jsx            # REACT ENTRY POINT: Mounts the `App` component to the HTML DOM.
│   └── index.css           # GLOBAL STYLES: Contains Tailwind directives and foundational CSS rules.
├── index.html              # The single HTML file that loads the React application.
├── vite.config.js          # Configuration for the Vite build tool.
└── package.json            # Lists React/Vite dependencies and build scripts.
```
